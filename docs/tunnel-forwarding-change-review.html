为什么这个仓库也要改

主仓修复了远端 EH ready 被 language pack 安装卡住的问题，但 streamlocal 失败的第一阶段发生在 open-remote-ssh 插件内部。之前插件只打印 Opening tunnel local => remote，本地 listener 创建成功后就像“已连接”，真正每条 WebSocket 连接触发的 openssh_forwardOutStreamLocal 错误没有直接进入 Remote-SSH output。

评论：这个修改不是为了让 kfs 从 socket 模式变通。 kfs 的核心 workaround 仍然是保持 remoteServerListenOnSocket=false 走 TCP。这个插件仓改动是为了下一次遇到类似机器时，日志能直接告诉我们是 direct-streamlocal@openssh.com 被拒，还是普通 direct-tcpip 失败。

代码评论

1. 底层 tunnel 失败事件带上连接上下文

src/ssh/sshConnection.ts

const connectionId = ++this.__tunnelConnectionSeq;
const localConnection = this.describeSocket(socket);
const remoteTarget = SSHTunnelConfig.remotePort
  ? `${SSHTunnelConfig.remoteAddr}:${SSHTunnelConfig.remotePort}`
  : SSHTunnelConfig.remoteSocketPath!;
评论：connectionId 是排查关键。 resolver 创建的是一个本地 listener，后续 Management / ExtensionHost / 其他通道会分别连进来。给每条 accepted socket 编号后，可以把“哪一次本地连接”与“哪一次 SSH channel open 失败”对齐。

2. 区分 TCP 和 streamlocal

src/ssh/sshConnection.ts

this.emitTunnelDisconnect(SSHTunnelConfig, err, {
  connectionId,
  forwardingType: 'direct-streamlocal@openssh.com',
  localConnection,
  remoteTarget
});
评论：这会把 kfs 这类问题从 240 秒 timeout 变成一条明确错误。 以前只能在 renderer 里看到 WebSocket 1006，或者去远端 /var/log/secure 找 sshd 记录。现在 Remote-SSH output 就能看到 streamlocal channel 的原始错误和远端 socket path。

3. 上层输出到 Remote-SSH 日志

src/authResolver.ts

this.logger.error(
  `Tunnel connection failed: tunnel=${tunnelConfig.name}, connectionId=${connectionId}, ` +
  `type=${forwardingType}, local=${localConnection}, remote=${remoteTarget}`,
  payload.err
);
评论：这里选择 output channel，而不是只 emit 事件。 用户和排障者通常看的就是 “Remote - SSH” output。把事件落到日志里，才方便确认是不是服务器策略、SELinux/sshd 加固、ProxyJump 或 TCP forwarding 问题。

4. 失败时立即关闭本地 socket

src/ssh/sshConnection.ts

if (err) {
  this.emitTunnelDisconnect(...);
  closeSocket();
  return;
}
评论：这是用户体验上的小修复。 如果 SSH channel 已经打开失败，本地 socket 继续挂着只会让 renderer 侧等到更不透明的 websocket timeout。立即关闭能让失败更快浮出水面。

变更文件

文件 说明
src/ssh/sshConnection.ts 为每条 tunnel connection 记录上下文，失败时 emit 结构化错误并关闭 socket。
src/authResolver.ts 订阅 tunnel disconnect 事件，并把 per-connection 失败写入 Remote-SSH output。

失败日志会长什么样

Tunnel connection failed:
tunnel=ssh_tunnel_61698_/run/user/0/vscode-server-sock-...
connectionId=2
type=direct-streamlocal@openssh.com
local=127.0.0.1:54321 -> 127.0.0.1:61698
remote=/run/user/0/vscode-server-sock-...
评论：看到 type 就能直接判断方向。 direct-streamlocal@openssh.com 失败，优先查 Unix socket forwarding。direct-tcpip 失败，再查普通端口转发或远端 server 端口。

保留判断

建议保留。 它不改变成功路径，却显著提升失败路径可观测性。对“其他人机器为什么连不上”的排查很有价值。
风险很小。 主要行为变化是转发失败时立即 destroy 本地 socket；这与 SSH channel 已失败的事实一致，避免后续无意义等待。
